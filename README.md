# GymTracker - ジムトレーニング記録アプリ

iPhoneで簡単にジムでのトレーニング記録を管理するアプリです。

## 機能

### 📱 ホーム画面
- **天気表示**：東京都豊島区の気温とアイコン表示
- **今日のメニュー**：曜日ごとのトレーニングメニューを自動表示
- **クイックアクション**：トレーニング開始、メニュー管理、過去データ確認

### 🏋️ トレーニング記録
- **自動タイマー**：曜日ごとに異なる時間設定可能（デフォルト70分）
- **セットごと記録**：各セットの回数を個別に入力
- **進捗表示**：前回の同じ曜日との比較で回数が増えた場合は「+」、減った場合は「-」を表示
- **記録保存**：トレーニング終了時に自動保存

### ⚙️ メニュー管理
- **曜日別管理**：7曜日すべてのトレーニング種目を管理
- **簡単編集**：種目の追加・削除・編集が可能
- **フレキシブル**：いつでもメニューを変更可能

### 📊 データ分析
- **進捗グラフ**：曜日ごとのトレーニングボリューム（総回数）を可視化
- **履歴確認**：過去のトレーニング記録を閲覧
- **自動保護**：端末内に最大20世代のバックアップを保存し、LocalStorageの消失・破損を検知したときに自動復旧
- **バックアップ移行**：JSONファイルへの書き出しと、バックアップファイルからの復元に対応

### ⏱️ 設定
- **タイマー時間カスタマイズ**：各曜日のトレーニング時間を個別に設定

## 使い方

### 初回セットアップ

1. `setup-menu.html` をブラウザで開く
2. 「メニューを自動登録」ボタンをクリック
3. `index.html` を開く
4. ホーム画面に表示される

### iPhoneへのインストール

1. Safari で `index.html` を開く
2. 下部のシェアボタン → 「ホーム画面に追加」
3. ホーム画面からアプリを起動

## 使用方法

### トレーニング開始
1. ホーム画面の「トレーニング開始」ボタンをタップ
2. 各種目のセットごとに回数を入力
3. 「開始」でタイマースタート
4. トレーニング終了後「トレーニング終了」をタップ

### メニュー管理
1. ホーム画面の「メニュー管理」をタップ
2. タブで曜日を選択
3. 種目を編集または「種目を追加」で新しい種目を追加
4. 自動保存される

### 設定変更
1. ホーム画面の⚙️をタップ
2. 各曜日のトレーニング時間を入力
3. 自動保存される

## データ保存

- すべてのデータはiPhoneのローカルストレージに保存されます
- 変更時・起動時・バックグラウンド移行時に、端末内の別領域へ最大20世代を自動バックアップします
- 過去データ画面からバックアップファイルを書き出し、同じ画面から復元できます
- クラウド同期はありません
- 端末の故障・紛失やサイトデータ全消去に備え、書き出したファイルをiCloud Driveなど端末外にも保存してください

## 技術仕様

- **フロントエンド**：HTML5 + CSS3 + JavaScript
- **ストレージ**：LocalStorage（主保存）+ IndexedDB（端末内世代バックアップ）
- **天気API**：Open-Meteo（無料）
- **グラフ表示**：Chart.js
- **PWA対応**：オフラインで動作可能

## 無音AI音声記録

ホームの「声でトレーニングを記録」、または「トレーニング開始」後の画面内「声で記録」から使います。読み上げ・通知音・タイマー音は出しません。確定したセットは通常の記録フォームと履歴へ反映します。以前のテスト記録は別扱いで保持します。

1. GitHub Pages上では自動接続します（接続パスワードの手入力は不要）。OpenAIのAPIキーはブラウザに入力しません。接続トークンは約12時間有効で、期限切れ時も自動で再取得します。
2. 「録音を開始」を押し、マイク許可と入力機材（DJI Mic Miniなど）を確認します。画面を前面・点灯状態に保ちます。
3. 未登録の種目名は仮記録になり、「確認」→「これで合っていますか？」でメニュー登録してから保存します。
3. 「ベンチプレス70キロ8回」「6回」「65キロで8回」「インクラインダンベルプレス20キロ10回を3セット」「ディップス自重で10回8回6回」と話します。全曜日の登録種目と代替種目が候補です。合図の「記録」は不要です。
4. 「筋トレ終了」で発話と記録をAIが照合します。確認待ちがあれば画面を見て「ベンチプレスの2セット目を7回に訂正」「確認待ち1は無視して」などと話します。
5. 「確認して保存」で記録全体を確定し、一時録音を削除します。確認待ちや未処理区間が残る場合は確定しません。確定済みのセット自体は途中でも通常履歴に保存します。

録音はAudioWorkletで1秒ごとに16kHz/16bit PCMとしてIndexedDBへ保存します。音量による発話検出で前後の音を含め、無音3秒で送信単位を区切ります。休憩中も端末への録音は継続し、無音部分を通常はAPIに送りません。40秒を超える長い発話は重ならない区間に分割し、境界を含む区間を自動確定せず確認待ちにします。音量検出は本人判別ではなく、静かな声を見落とす可能性があるためマイク実機試験が必要です。

通信断では送信待ちを保持して順番に再送します。処理IDと記録・ジョブ完了の一括保存により二重登録を防ぎます。再起動時は未処理録音を復旧し、録音の中断を記録します。約80分で約154MBの録音容量を使い、開始時は約190MB以上の空きを確認します。保存済みの試験は選択欄から開けます。旧試作のLocalStorageは削除しません。

### メニュー表示とiPhoneの制約

録音画面内で曜日を選び、登録メニュー・同じ曜日の直近の通常履歴・今回の音声セットを比較できます。前回は今回より前の日付に限定し、セット別重量と共通重量の両方を表示します。履歴の書き換えは行いません。

画面が非表示になっただけでは録音を止めません。ただしAudioContext停止、マイク中断、音声ブロックの6秒以上の受信空白を検知したら中断として残します。iPhoneでの画面ロック中の継続・Spotifyとの同時再生は未保証です。Web版にはネイティブのAVAudioSessionのmixWithOthers設定はありません。無音音声での延命は追加しません。

短い小声を1秒平均で見落とさないよう20ms単位で入力を判定します。数字の文字起こしlogprobが-1.5未満の場合は確認待ちにします。このしきい値は保守的なヒューリスティックであり、認識精度の保証や校正済み確率ではありません。

### APIと鍵の管理

- フロント：GitHub Pages。中継：`voice-worker/`のCloudflare Worker。
- 音声認識：`gpt-4o-transcribe`、構造化・終了照合：`gpt-4.1-mini`。
- Worker Secrets：`OPENAI_API_KEY`、`AUTH_SECRET`、`USER_PASS_HASH`（ランダム専用パスワードのSHA-256）。キー・パスワードはGitに入れません。
- 利用者認証は12時間の署名付きトークン。ログインはIPごと10回/分、認証後はDurable Objectで30回/分、600回/UTC日、音声180分/UTC日を上限にします。再試行も上限に含みます。
- 音声と登録種目・必要な記録をCloudflare経由でOpenAIへ送信します。Workerは録音や文字起こしを永続保存せず、利用量カウンターだけを保存します。OpenAI側のデータ保持条件は別途適用されます。
- Aqua APIへの送信は未実装・無効です。同じテスト音声で比較する場合は、Aquaへの送信を明示してから追加します。

### 検証

`node --test tests/ai-voice.test.cjs tests/ai-voice-runtime.test.cjs tests/voice-worker.test.mjs`

単発・引継ぎ・重量変更・まとめ記録・自重・訂正・予定を無視する操作・曖昧値・分割境界・再送・録音削除・認証・利用上限を検証します。80分相当のPCMブロック連番テストは、実時間のiPhone録音テストとは異なります。`tests/live-voice-smoke.cjs`は明示的に実行する有料API接続試験で、ローカル生成した合成日本語音声だけを送信します。

実機の合格条件は、80分間の手操作不要・音声出力なし・録音欠落なし・発話と最終記録一致・曖昧な値を勝手に確定しないことです。iPhoneと購入マイクでの試験は未実施です。実機での連続録音は引き続き未検証です。ユーザーの指定により通常履歴への接続を有効にしました。新規の音声記録はliveモードで、確定したセットをgym_recordsへ自動反映します。以前のvalidation記録は自動では取り込みません。

## 一般的な問題

### データが表示されない
- キャッシュをクリアして再度開く
- `setup-menu.html` でメニューを再登録

### 天気が表示されない
- インターネット接続を確認
- Open-Meteo APIが利用可能か確認

### タイマーが音を出さない
- ブラウザの音声設定を確認
- 通知許可を確認

### 通常履歴への保存と削除（2026-09-11）

音声セットにはvoiceSessionIdとvoiceSetIdを付け、同じ日・曜日の既存セットを残して追加します。訂正・削除時はその音声記録の行だけを更新します。履歴保存が失敗した場合、音声と処理結果を保持して再試行できます。最終確定は通常履歴への書き込み成功後に録音を削除します。

セット横の削除は1タップ、記録全体の削除は画面内の確認を挟みます。全体削除は対象セッションの録音・ジョブ・音声記録をIndexedDBの同じトランザクションで消します。旧テスト記録も選択して削除できます。通常履歴で後から手入力編集し音声の識別情報が失われた行は、音声画面からの一括削除対象にできません。

検証：node --test tests/ai-voice*.test.cjs tests/voice-worker.test.mjs
